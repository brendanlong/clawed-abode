# Components

Must-knows for the message display system (`messages/`); the upstream message pipeline is documented in `doc/messages-and-sse.md`.

- `MessageList` renders the transcript; its decisions are pure helpers in `messageHelpers.ts` — put new list logic there so it stays unit-testable. `buildTranscriptLayout` derives the rows to render. Scroll behavior lives in `useTranscriptScroll` (`src/hooks/`), except keeping the view in place when an older page is prepended, which is `KeepTopRowInPlace` — explicit because CSS scroll anchoring is missing in Safari and inert at `scrollTop` 0; don't hand that back to `overflow-anchor`. Scans over tool calls go through the `toolUseBlocks` iterator rather than re-walking `content.message.content`, and assume `messages` is already chronological — don't re-sort. That order comes from `getHistory` sorting each page, `prependOlderPage` prepending older pages, and `mergeMessageIntoCache` inserting live messages by sequence (all in `src/lib/message-cache.ts`); keep all three if you touch them.
- **A transcript update re-renders only the bubbles it touches.** Without this, each streamed partial re-rendered every loaded bubble (~270 ms per partial at 900 rows on a 4x-throttled phone, #654). `MessageBubble` is memoized by `messageBubblePropsEqual`: the same message fields by reference, plus the same `ToolResult` object for each of its own calls. Keep those identities across updates: cache writes reuse the message objects they keep, the transcript query has structural sharing off, and per-message derivations are memoized by object (`memoizeByObject`, as `toToolResult` and the classifier are). Data that changes with the rest of the transcript (subagent transcripts, the latest TodoWrite, plan content) is never a `MessageBubble` prop; the card that shows it reads it from `useMessageListTranscript`, so only that card re-renders. Any other context a bubble itself reads must keep a stable value across transcript updates: `useMessageListActions`, `useVoicePlaybackEnabled` (not the whole playback state, which changes as audio plays).
- **To add a specialized tool renderer**: create `XxxDisplay.tsx` in `messages/`, read its input through `parseToolInput` with a Zod schema of `lenient(...)` fields (never cast `tool.input`; one wrong-typed field must not blank the whole display), and register it in `TOOL_DISPLAY_MAP` in `ContentRenderer.tsx`. Unknown tools fall back to the generic `ToolCallDisplay`; unknown message types to `RawJsonDisplay`.
- A call's result (`ToolCall.result`) carries its body only when it was small; large ones arrive as a summary (`doc/messages-and-sse.md`). So collapsed card content (badges) reads `result.summary`, and anything that shows the output goes in `ToolDisplayWrapper`'s render-function children, which get the text once it is loaded (fetched only while expanded). Never read `result.text` for what a collapsed card shows.
- Both the `Agent` and legacy `Task` tool names must stay mapped to `SubagentToolDisplay`: subagent grouping keys off `parent_tool_use_id` (not the tool name), so the only failure mode is the parent call not routing to `TaskDisplay`, which makes the whole grouped transcript unreachable.
- Subagent transcripts render through the `renderSubagentTranscript` callback from `useMessageListTranscript` rather than a direct import, to avoid a `TaskDisplay` → `MessageBubble` module cycle; nested subagents recurse through the same context. A refusal fallback's retracted attempt renders under its banner through `renderRetractedMessages` for the same reason.
- Which messages render as rows is decided only by `messageDisplay` / `isTranscriptRow` ([`src/lib/transcript-display.ts`](../lib/transcript-display.ts)) — the classifier the server stores as `Message.display` and pages history by (see `doc/messages-and-sse.md`). The top-level list takes `messageDisplay === 'row'`, each `NestedTranscript` takes `isTranscriptRow`; don't filter rows by any other rule. Lists filter with it (no empty spacer row) and `MessageBubble` checks it too. Tool results never render on their own, only on their call.
- Background-subagent boxes are **relocated** (breadcrumb at spawn, live box pinned at the bottom, settled inline at finish) so concurrent main-agent output doesn't read as ungrouped subagent activity. The placement decision is the pure `computeSubagentPlacements` over `collectSubagentLifecycles` — extend there (exhaustively unit-tested); the wiring is covered by `MessageList.test.tsx`. A foreground subagent with nothing interleaved renders inline. Grouping/relocation is rendering-only; everything but `hidden` messages is paged and streamed.
- Timestamps mark **turn boundaries only** (user prompt, result row, interrupt marker) so the transcript stays quiet; `MessageBubble` shows one only when handed `createdAt`, which nested subagent rows never are (they aren't turn boundaries).
